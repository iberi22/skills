# Parametric vehicle templates

A template turns a `VehicleSpec` (real measurements in mm + tire sizes + paint) into a
`BuiltVehicle`: a `three` object tree where each serviceable part lives in its own slot group
`part:<slotId>`. No downloaded models, no AI, no images of real vehicles: geometry is code.

Read first: `src/garage/contracts.ts` (VehicleTemplate, BuiltVehicle, RENDER_BUDGET),
`src/garage/parts.ts` (slot ids per family), `src/garage/templates/common/` (geometry kit,
material kit, `buildWheel`). Copy the structure of `common/debugTemplate.ts`.

## Space conventions (non-negotiable)

Meters. +Y up, ground at y = 0 (tires touch it: `minY` in the lab must be 0 ± 2 mm). Front faces
+X. Width on Z (+Z = rider/driver left). Wheelbase centered on x = 0: front axle at
`+wheelbase/2`, rear axle at `-wheelbase/2`. Convert mm only with `mm()` from `common/units.ts`.

## What must be exact vs. what is style

| Exact (from the spec, test it) | Style (template decides, via shapeParams) |
|---|---|
| wheelbase, axle positions | tank/roof/hood curvature |
| tire outer radius & width (`buildWheel`) | panel bevels, seams, vents |
| overall length / width / height within ±3 % | rim spoke count/style (variants) |
| track width (cars) if given | lights shape (generic only) |
| seat height (motos) if given, ±5 % | exhaust routing variants |

## Trademark-free rules (the reason these templates exist)

- Generic archetypes only: "moto naked", "sedán compacto". Never reproduce a specific model's
  signature: no kidney/7-slot/spindle grilles, no brand light signatures (no "Thor hammer",
  no "angel eyes"), no badges, emblems, logos, model names or letters anywhere in geometry
  or textures. Badge areas stay blank.
- Two templates of the same family must be distinguishable by proportions, not by copying
  a manufacturer's design cue.
- Brand names exist only as user data in text (the UI), never inside the 3D.

## Construction toolkit (common/geometry.ts)

- `loft(sections)` + `bodySection({...})` — car bodies, cabins, moto tanks/tails/fairings. 8–14
  sections along X, 24–40 points per ring (LOD high), half that on low. Narrower top than bottom
  (`halfWidthTop < halfWidthBottom`) gives the "tumblehome" that makes bodies look real.
- `extrudeProfile(points, { depth, bevel })` — side-profile panels: fenders, side covers,
  swingarms, bumpers, door skins. Always bevel (2–8 mm): hard 90° edges look like placeholder art.
- `tube(points, r)` — trellis frames, handlebars, exhaust headers, fork tubes.
- `roundedBox` — batteries, calipers, engine blocks, light housings.
- `buildWheel({ tire, family, style, paint, side, rear })` — always use it for wheels; place
  `tire`, `rim`, `brake` in slots `tire_*`, `rim_*`, `brake_*`.
- `part(slotId, ...meshes)` — every mesh must end inside exactly one slot group.
- Materials **only** from `ctx.materials` (`paint`, `accent`, `rubber`, `metal(kind)`, `chrome`,
  `plastic(kind)`, `glass(kind)`, `light(kind)`, `carbon`, `seat`). Painted panels use
  `paint(spec.paint)`; mechanical parts use dark metal / textured plastic so the paint reads.

## Visual quality bar (reference: stylized hard-surface "concept bike" look)

Readable silhouettes first, detail second. A template is not done until, in the lab side view,
a person can tell *what kind of vehicle* it is from the silhouette alone, and the 3/4 view shows
believable volumes (no flat cardboard sides, no floating parts, no gaps between body and wheels
that the real thing wouldn't have). Mechanical parts (engine, exhaust, suspension, chain) are
dark/metallic and visible on motos; on cars they are `internal` and shown only in x-ray.

## Budgets & LOD

`RENDER_BUDGET.vehicleTrianglesHigh` (90k) / `vehicleTrianglesLow` (35k). Merge static sub-meshes
*within a slot* when they share a material (`mergeGeometries`) — draw calls per vehicle ≤ 70.
`ctx.lod === 'low'` → halve ring points/sections, drop small details (bolts, vents, grooves).

## Template file shape

```ts
export const SEDAN: VehicleTemplate = {
  id: 'car-sedan', family: 'car', body: 'sedan', label: 'Sedán compacto',
  defaults: { family, body, dims: {...typical mm...}, tireFront, tireRear },
  shapeParams: [{ id: 'roofSlope', label: 'Caída del techo', default: 0.5 }, ...],
  variants: { rim_fl: ['spokes', 'split', 'disc'], ... },
  build(spec, ctx) { ...; return { root, parts, focusPoints, triangles: countTriangles(root) }; },
};
```
Read shape params with a default: `const roof = spec.shape?.roofSlope ?? 0.5;` — every param must
stay valid over the whole 0..1 range (test 0, 0.5, 1).

## Tests (vitest, node — no GPU needed; geometry and node materials build fine in node)

For every template: builds with defaults and with shape params at 0 and 1; all
`requiredSlots(family)` present in `parts` and named `part:<slot>` in the tree; bounding box
length/height/width within ±3 % of `dims` (width may exclude mirrors); `minY` ≈ 0; wheel centers
at ±wheelbase/2; triangles ≤ budget for both LODs; no NaN in any position attribute.

## Visual verification (mandatory — look at the PNGs)

```bash
ASTRO_DEV_BACKGROUND=0 npx astro dev --port <port> --host 127.0.0.1 --ignore-lock &   # ver nota
for v in side three-quarter front rear; do
  node scripts/garage-shot.mjs --base http://127.0.0.1:<port> --template <id> --view $v --out /tmp/<id>-$v.png
done
```
The script prints real size in mm, triangles, draw calls and slots. Compare against the spec,
then open the images and fix what looks wrong. Iterate until it looks good; a template that
passes tests but looks like boxes on wheels is not done.
